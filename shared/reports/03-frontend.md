## [2026-11-21] ElevenLabs 클라이언트 로직 분석 (1단계) — 완료
모델·effort 검토: opus/high는 판단과 최종 정리에 적정. 에이전트 SDK 문서 요약은 sonnet 서브에이전트 1개에 맡겼고, 핵심 주장은 원문과 대조해 확인함.
- 산출물: `shared/research/elevenlabs/03-frontend-client-logic.md`
- 녹음 화면 관찰:
  - 파일 입력이 여러 파일을 받고, 오디오와 비디오 MIME을 함께 허용한다.
  - 페이지에 들어가기만 해서는 마이크 권한을 요청하지 않는다(`prompt` 상태 유지).
- 녹음 제한:
  - 문서 기준: 파일당 최소 5초, 합계 최소 10초, 권장 1~2분, MP3 192kbps 권장.
  - 10MB 제한은 앱 UI 문구에만 있다.
- 녹음 구현안: `MediaRecorder`(webm/mp4), 3분 자동 정지, 길이·용량을 클라이언트와 서버 양쪽에서 검증, `AnalyserNode` 파형. API 키는 서버에만 둔다.
- 재생 관찰: 미리듣기는 `<audio>`로 GCS의 mp3를 재생한다.
- 재생 구현안: 서버가 `/stream` 응답을 중계해 `<audio>`로 재생한다. 저지연이 필요하면 PCM을 받아 Web Audio 큐로 재생한다.
- 스트리밍 구현안: TTS `stream-input` WebSocket에 일회용 토큰(`tts_websocket`, 15분)으로 브라우저가 직접 연결한다.
- 에이전트: 위젯은 public agent 전용이다. SDK는 음성을 WebRTC(`pcm_48000` 고정)로, 텍스트를 WebSocket으로 연결하고, private agent는 signed URL(15분 안에 연결 시작)이나 conversation token을 쓴다.
- 앱 스택: Next.js 16.4.5(App Router, Turbopack), React, Tailwind, Radix, `api.us.elevenlabs.io` 직접 호출.
- 우리 스택 제안: Next.js + TypeScript + Tailwind/Radix + TanStack Query + 브라우저 표준 오디오 API(npm).
- **막힌 점 / 실행 확인 필요**:
  1. 녹음 버튼 이후 흐름: 마이크 녹음이 금지 항목이라 확인 못 함.
  2. TTS 생성 결과의 재생 방식: 생성 버튼을 눌러야 해서 확인 못 함.
  3. `/stream` 응답 형식: 문서끼리 다르다(SSE ↔ 원시 바이트). 호출해야 알 수 있다.
  4. 업로드 오류 문구: 파일 업로드가 금지 항목이라 확인 못 함.
- **요청 사항**:
  - 백엔드팀: 스트림 중계 경로, 업로드 서버 검증과 MP3 변환, 일회용 토큰 발급 경로.
  - 디자인팀: 녹음 상태별 화면 시안.
  - QA팀: 브라우저별 녹음 포맷 차이와 권한 거부 시나리오.
- 앱 조작 내역: 새 탭에서 관찰하고 닫았다. 누른 것은 라이브러리 미리듣기 재생 1회뿐이며 바로 정지했다.
